Lição 1: Entendendo o Stack do Core Data

⏱️ 15 minutos • 🎯 Iniciante • 🔧 Exercício Prático

Objetivo de Aprendizado

Ao final desta lição, você entenderá a arquitetura do stack do Core Data e será capaz de identificar cada componente no seu app PokePrice. Esta fundação é essencial para construir aplicativos iOS robustos com persistência.

O Stack do Core Data

Core Data é um framework de gráfico de objetos e persistência que permite trabalhar com dados como objetos, em vez de lidar com consultas de banco de dados cruas. O stack consiste em vários componentes-chave que trabalham juntos:

Componentes Chave

  • NSPersistentContainer - O container de alto nível que gerencia o stack do Core Data
  • NSManagedObjectModel - Define o modelo de dados (entidades, atributos, relacionamentos)
  • NSPersistentStoreCoordinator - Coordena entre o modelo e os stores persistentes
  • NSPersistentStore - Onde os dados são realmente salvos (SQLite, binary, in-memory)
  • NSManagedObjectContext - O espaço de trabalho para manipular objetos gerenciados
💡 Ponto Chave: Pense no NSPersistentContainer como o "regente de orquestra" que coordena todos os outros componentes para você.

Sua Implementação Atual

Vamos examinar o stack do Core Data que você acabou de implementar no PokePrice. Abra o CoreDataStack.swift e vamos identificar cada componente:

lazy var persistentContainer: NSPersistentContainer = {
    let model = CoreDataModelSetup.createManagedObjectModel()
    let container = NSPersistentContainer(name: "PokePriceDataModel", managedObjectModel: model)
    
    container.loadPersistentStores { description, error in
        if let error = error {
            fatalError("Core Data store failed to load: \(error.localizedDescription)")
        }
    }
    
    container.viewContext.automaticallyMergesChangesFromParent = true
    container.viewContext.mergePolicy = NSMergeByPropertyObjectTrumpMergePolicy
    
    return container
}()

Decomposição de Componentes

  • NSManagedObjectModel: Criado por CoreDataModelSetup.createManagedObjectModel()
  • NSPersistentContainer: A variável container que encapsula tudo
  • NSPersistentStore: Criado automaticamente quando loadPersistentStores é chamado
  • NSManagedObjectContext: Acessado via container.viewContext

Contextos e Threading

Sua implementação usa dois contextos - este é um padrão crucial para performance:

var viewContext: NSManagedObjectContext {
    return persistentContainer.viewContext
}

var backgroundContext: NSManagedObjectContext {
    let context = persistentContainer.newBackgroundContext()
    context.mergePolicy = NSMergeByPropertyObjectTrumpMergePolicy
    return context
}
⚠️ Importante: Contextos do Core Data não são thread-safe. Sempre use o contexto de background para operações que podem bloquear a thread principal.
  • View Context: Contexto da thread principal para atualizações de UI
  • Background Context: Thread de background para operações pesadas (chamadas de rede, grandes conjuntos de dados)

Armadilhas Comuns

❌ Erro: Usar o contexto errado para a operação
✅ Correção: Sempre use contextos de background para operações de rede e computações pesadas
❌ Erro: Não lidar com erros do Core Data graciosamente
✅ Correção: Sua implementação atual usa fatalError - em produção, você precisaria de melhor tratamento de erros
