Glossário de Core Data

📖 Referência Rápida • 🔄 Atualizado conforme você aprende

Componentes do Stack do Core Data

NSPersistentContainer

O container de alto nível que encapsula todo o stack do Core Data. Introduzido no iOS 10, simplifica a configuração do stack ao lidar automaticamente com a criação e configuração do modelo, coordenador e contextos.

NSManagedObjectModel

Define o schema dos seus dados incluindo entidades, atributos e relacionamentos. Pense nele como a definição do schema de banco de dados mas em termos orientados a objetos.

NSPersistentStoreCoordinator

Coordena entre o modelo de objetos gerenciados e os stores persistentes. Gerencia o armazenamento real dos dados e lida com coisas como migração e configurações de múltiplos stores.

NSPersistentStore

O mecanismo de armazenamento real onde os dados são persistidos. Tipos comuns incluem SQLite (padrão), binário e stores em memória.

NSManagedObjectContext

O espaço de trabalho onde você cria, busca e manipula objetos gerenciados. Contextos não são thread-safe e cada thread deve ter seu próprio contexto.

Objetos do Core Data

NSManagedObject

A classe base para todos os objetos de modelo do Core Data. Estes representam seus dados na memória e são gerenciados por um contexto.

NSEntityDescription

Descreve uma entidade no modelo de dados, incluindo seu nome, atributos e relacionamentos. Equivalente a uma definição de tabela em bancos de dados tradicionais.

NSFetchRequest

Usado para recuperar dados do Core Data. Similar a declarações SELECT do SQL mas expresso em termos de objetos e predicados.

NSPredicate

Define critérios de filtragem para fetch requests. Pense nele como a cláusula WHERE em consultas SQL.

Conceitos do Core Data

Entity (Entidade)

Uma definição de classe no seu modelo de dados. Representa um tipo de objeto que você quer armazenar, como "CachedCard" ou "ScanHistory". Equivalente a uma tabela em um banco de dados.

Attribute (Atributo)

Uma propriedade de uma entidade, como "cardId" ou "name". Atributos definem os dados que uma entidade armazena. Equivalente a colunas em uma tabela de banco de dados.

Relationship (Relacionamento)

Define como as entidades se relacionam entre si, como um-para-um, um-para-muitos ou muitos-para-muitos. Equivalente a chaves estrangeiras em bancos de dados.

Managed Object Context

O rascunho onde você manipula objetos gerenciados. Mudanças feitas em um contexto não são persistidas até você chamar save().

Conceitos Avançados

Merge Policy (Política de Merge)

Determina como conflitos são resolvidos quando múltiplos contextos tentam salvar os mesmos dados. Políticas comuns incluem NSMergeByPropertyObjectTrumpMergePolicy e NSOverwriteMergePolicy.

Faulting

O mecanismo de lazy loading do Core Data. Objetos não são totalmente carregados na memória até você acessar suas propriedades, o que melhora a performance.

Migration (Migração)

O processo de atualizar seu modelo de dados quando você faz mudanças em entidades, atributos ou relacionamentos. O Core Data fornece estratégias de migração lightweight e heavyweight.

Concurrency (Concorrência)

O Core Data suporta múltiplos contextos rodando em diferentes threads. O modelo de confinamento de fila garante thread safety ao associar cada contexto a uma fila de dispatch específica.

Tipos de Store

SQLite Store

O tipo de store mais comum e padrão. Usa arquivos de banco de dados SQLite para armazenamento e consulta eficiente. Suporta consultas complexas e relacionamentos.

Binary Store

Armazena dados como arquivos binários. Mais simples mas menos eficiente para grandes conjuntos de dados. Bom para pequenas quantidades de dados ou quando você precisa portabilidade.

In-Memory Store

Armazena dados apenas na RAM. Os dados são perdidos quando o app termina. Útil para testes, cache ou dados temporários.
